# Components and Composition

A reusable circuit component is a Plan-level object. It can expose public pins, own private internal nodes, contain primitive elements, contain subcomponents, and define local parameters.

Component composition is Plan-level hierarchy. It is not compiled-netlist-level concatenation.

Canonical physics:

- [Josephson current, phase, energy, and inductance](https://github.com/arfiligol/SCQ_Design/blob/main/docs/knowledge/josephson-physics/josephson-current-phase-energy-and-inductance.qmd)
- [Josephson cosine and quantum anharmonicity](https://github.com/arfiligol/SCQ_Design/blob/main/docs/knowledge/josephson-physics/josephson-cosine-and-quantum-anharmonicity.qmd)
- [dc SQUID flux tunability](https://github.com/arfiligol/SCQ_Design/blob/main/docs/knowledge/josephson-physics/dc-squid-flux-tunability.qmd)

<Aside type="caution" title="Current implementation boundary">

Julia Core currently implements a single `JosephsonJunction` relation with Josephson-inductance binding and nonlinear `Lj...` solver lowering. It does not provide `SQUID(...)`, `SingleJunction(...)`, `squid_loop(...)`, external-flux binding, junction-asymmetry, or loop-inductance lowering. Those names below are conceptual component-library sketches, not executable APIs.

</Aside>

## Example Component Families

<Aside type="caution" title="Examples, not an ownership decision">

The families below may live in the Julia Core reusable component catalog or an
external Component Library. Placement depends on the ownership boundary, not
on whether the component is concrete.

</Aside>

Reusable families may include:

| Family | Examples |
| --- | --- |
| Primitive Elements | `Capacitor`, `LinearInductor`, `JosephsonJunction` |
| Inductive Elements | `LinearInductor`, `SingleJunction`, `SQUID` |
| Lumped Resonator Components | `GroundedLCResonatorComponent`, `FloatingLCResonatorComponent` |
| Distributed Components | `ReadoutLineComponent`, `CPWFluxLineComponent`, `QuarterWaveResonatorComponent`, `HalfWavePurcellFilterComponent` |

These examples may be used directly or inside composite components. Composite
components may contain smaller components and primitive elements.

## Ownership Rule

Under the accepted V1 ownership contract, Julia Core owns the
component authoring contract and may own stable local topologies used as
components inside larger circuit topologies.

External Component Libraries may own component variants intentionally kept in
user, lab, process, device-family, or project space. Specificity alone does not
exclude a stable local topology used by a larger topology from Core. Project
Plan Builders own complete research circuits expressed as `CircuitPlan`,
including their external ports, targets, and study policy.

A component library may provide:

- primitive physical elements;
- composite resonator components;
- distributed line components;
- nonlinear elements;
- lab-specific chip blocks;
- project Plan Builders;
- validation helpers specific to that component family.

All components must satisfy the same authoring, endpoint, validation, and
compiler contracts. See
[Component Libraries](component-libraries.md) for the candidate ownership
criteria and decision table.

## Composition Rules

| Rule | Contract |
| --- | --- |
| Public pins | Components expose stable user-facing attachment names such as `:signal`, `:plus`, `:minus`, or `:feed`. |
| Private internal nodes | Components may own internal implementation nodes; users should not need those names. |
| Subcomponents | Composite components may include smaller components and primitive elements. |
| Local parameters | Components may carry local values, sweep knobs, and provenance. |
| Line references | Distributed components with multiple internal lines must expose named line references such as `line_ref(component,:main)`. |
| Namespacing | The compiler namespaces private nodes and subcomponent internals when it expands hierarchy. |
| Flattening | Composite components are flattened by the global compiler after endpoint resolution and validation. |

<Aside type="caution" title="Reusable units">

Compiled netlist fragments should not be used as reusable components. Reuse the Plan-level component and let the global compiler lower the complete Circuit Plan.

</Aside>

## Composite Examples

The following examples describe composition patterns built on the Julia Core
Kernel:

```text
SQUID
  = JosephsonJunction + JosephsonJunction + optional loop inductance + flux parameter

GroundedLCResonator
  = Capacitor(signal, ground) + InductiveElement(signal, ground)

FloatingLCResonator
  = Capacitor(plus, minus) + InductiveElement(plus, minus)
```

This hierarchy states the executable component topology. The reusable physics,
mode impedance, and intrinsic/raw/PTC/wave observable layers are canonical in
SCQ_Design [Ideal Parallel LC Resonator](https://github.com/arfiligol/SCQ_Design/blob/main/docs/knowledge/network-modeling/ideal-parallel-lc-resonator.qmd).

The same high-level resonator component can accept replaceable inductive elements.

## Grounded LC With Replaceable Inductive Elements

The following example assumes a component library provides a grounded LC resonator builder and replaceable inductive element definitions.

```julia
lc1 = add_grounded_lc_resonator_component!(
  plan;
  id = "lc1",
  capacitance = Capacitor(80.0fF),
  inductive_element = LinearInductor(8.0nH),
)

lc2 = add_grounded_lc_resonator_component!(
  plan;
  id = "lc2",
  capacitance = Capacitor(75.0fF),
  inductive_element = SingleJunction(Ic = 25.0nA, Cj = 2.0fF),
)
```

The user changes the inductive element without changing the resonator's public attachment model.

## Conceptual Grounded LC With SQUID

The following non-executable sketch shows what a future component library would need to own.

```text
flux_line = add_cpw_flux_line_component!(plan; id = "flux", line_spec = flux_line_spec)

lc = add_grounded_lc_resonator_component!(
  plan;
  id = "squid_lc",
  capacitance = Capacitor(80.0fF),
  inductive_element = SQUID(
    junction_a = JosephsonJunction(Ic = 25.0nA, Cj = 2.0fF),
    junction_b = JosephsonJunction(Ic = 25.0nA, Cj = 2.0fF),
    external_flux = Parameter(:phi_ext),
  ),
)
```

A future SQUID would remain a component hierarchy in the plan. Core does not currently expose or lower its loop endpoint.

Distributed components from a component library may also expose line references for taps and spans:

```julia
main_line = line_ref(flux_line,:main)
tap = line_tap(main_line; at_m = 2.0mm)
```

The component-level shorthand `line_tap(flux_line; at_m = 2.0mm)` is valid only when the component has one unambiguous default line. Multi-line components must use `line_ref` or pass `line =:main`.

## Floating LC With Replaceable Inductive Element

The following non-executable sketch assumes a future component library provides a floating LC resonator builder and SQUID definition.

```text
flc = add_floating_lc_resonator_component!(
  plan;
  id = "flc",
  capacitance = Capacitor(80.0fF),
  inductive_element = SQUID(...),
)
```

Floating components expose two public attachment points, commonly `:plus` and `:minus`.

## Namespace Ownership

User-facing code should use public pins and endpoints:

```julia
pin(lc,:signal)
pin(flc,:plus)
pin(flc,:minus)
```

It should not require internal node names from the component implementation. Private names are compiler-managed and may change when the component hierarchy changes.
