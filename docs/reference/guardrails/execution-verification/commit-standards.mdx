# Commit Standards

Use a commit for one coherent, independently reviewable change. Branch, PR,
merge, and cleanup mechanics come from the active host delivery profile through
[Branch & Worktree Flow](branch-and-worktree-flow.mdx).

<Aside type="note" title="Coherent means reviewable">

A coherent commit has one purpose, includes the corresponding source and
required mirror updates, and has completed the checks required for its touched
area. It is not an unpublished WIP checkpoint.

</Aside>

## Commit Boundary

Commit when:

- the change is one logical unit;
- its required source and generated or extracted mirrors agree;
- the relevant Workbench checks for the touched paths pass; and
- the commit can be reviewed and reverted without pulling in unrelated work.

Do not commit incomplete behavior, unrelated formatting, or unrelated dirty
bytes merely to save local progress.

## Publication And History

- Push every coherent commit immediately to the branch selected by the active
  delivery profile.
- Do not leave a WIP commit as the only copy on one workstation.
- Do not amend, rebase, squash, or force-push already-published shared history.
- When the selected profile permits consolidation, Integration performs it at
  PR merge.

## Validation

Run the checks required by the touched-area rules and CI configuration. The
repository-wide pre-commit command can be useful when applicable, but it is not
a universal substitute for the actual docs, package, build, or CI checks named
for the changed surface.

## Commit Message

Use:

```text
<type>: <short description>
```

Common types are `feat`, `fix`, `docs`, `refactor`, `style`, `test`, and
`chore`.

## Agent Rule
```markdown
## Commit Standards
- Commit one coherent, independently reviewable change at a time.
- Include required source and extracted-mirror updates in the same coherent commit.
- Run the checks required for the touched Workbench surface; no single repository-wide command replaces those checks universally.
- Do not commit unrelated changes or use unpublished WIP commits as local checkpoints.
- Push every coherent commit immediately according to the active host delivery profile.
- Never amend, rebase, squash, or force-push already-published shared history; profile-permitted consolidation belongs to Integration at PR merge.
- Use `<type>: <short description>` with `feat`, `fix`, `docs`, `refactor`, `style`, `test`, or `chore` as appropriate.
```
