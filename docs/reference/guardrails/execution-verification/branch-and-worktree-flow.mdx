# Branch & Worktree Flow

This page is a repository adapter, not an independent GitFlow authority. Resolve
the readable host project's collaboration owner and selected delivery profile
before changing Git state, then follow that profile without weakening or
replacing it here.

<Aside type="caution" title="Host delivery policy is authoritative">

Do not infer permission for direct target-branch updates, development worktrees,
local integration, history rewriting, merge, synchronization, or cleanup from
this repository page.

</Aside>

## SCQ_Design Host

When Circuit Workbench is used inside SCQ_Design:

1. Load the installed `$scq-collaboration-roles` router.
2. Resolve the Workbench repository owner and the `standard-topic-pr` profile
   from its ownership registry.
3. Use the registered physical checkout, starting from a clean synchronized
   `origin/develop`.
4. Create one topic branch in that checkout, immediately push every coherent
   commit, and maintain one PR to `develop`.
5. Leave squash merge, exact-target verification, applicable pin or checkout
   synchronization, and safe cleanup to Integration & Sync.

The Workbench profile does not use a development worktree and does not authorize
direct development on `develop`.

## Other Hosts

Use the readable host's declared collaboration and delivery authority. If it
does not define one, this adapter grants no additional Git permission; preserve
existing bytes and obtain the missing authority before choosing a delivery
path.
