# Contributing Circuit Diagrams

> **Semantic status:** the SVG-only export-backed renderer pipeline, Manual
> integration, and Julia Core-versus-project placement guidance are
> **STABILIZED V1**.

Circuit diagrams are committed light and dark SVG documentation assets. The
default path starts from Julia Core circuit semantics:

```text
Julia Core builder
  -> CircuitPlan + SchematicLayoutIntent
  -> SchematicExportSpec
  -> schematic_export.json
  -> explicit Python visual mapping
  -> Schemdraw
  -> diagram.light.svg + diagram.dark.svg
```

The `CircuitPlan` remains the electrical source of truth.
`SchematicLayoutIntent` supplies renderer-neutral presentation intent. The
Python renderer selects a supported visual class from
`render_hints.schemdraw.component_type` and its labels and parameters; it does
not reconstruct arbitrary visual topology from netlist rows.

Schemdraw is not an application workflow, simulation runtime, or second
circuit-authoring model.

## Reusable-component clearance

Reusable Schemdraw dimensions are expressed relative to `unit_length`; do not
replace them with absolute drawing coordinates. A body-edge outward lead
defaults to `0.5u`, including `PortTerminal`. `Port50Ohm` instead uses a
`0.7u` terminal stub because its required clearance is measured from the
occupied resistor glyph bounding box: the supported `unit_length` range
`1.5–6` retains at least `0.5u` between that bound and the outer terminal.

`Port50Ohm` also reserves a `0.25u` lead between its signal junction and
resistor. Custom values must satisfy
`0 < load_lead_units < height_units` and leave at least one native Schemdraw
drawing unit for the IEEE resistor glyph:
`(height_units - load_lead_units) * unit_length >= 1`. A shorter span leaves
the electrical metadata connected but makes the fixed-minimum glyph overshoot
its ground anchor. These dimensions change drawing geometry only; physical
nodes, netlist topology, ports, and public terminals remain unchanged.

Parents connect at the child's outward public terminal and keep sibling native
glyph bounds disjoint. This is an explicit reusable-component contract, not a
generic auto-layout system. Font and label bounds still require review at the
rendered target size.

## Folder Contract

Create an export-backed diagram under `docs/assets/circuit_draw/`:

```text
docs/assets/circuit_draw/
├── _lib/
│  └── style.py
├── registry.yml
└── <topic>/<diagram_id>/
   ├── draw.py
   ├── diagram.yml
   ├── schematic_export.json
   ├── diagram.light.svg
   └── diagram.dark.svg
```

`schematic_export.json` is a committed, reviewable export fixture. `draw.py`
loads it, delegates to `schemdraw_circuit_library`, and defines
`build_drawing(theme="light") -> schemdraw.Drawing`.

`diagram.yml` records the reviewable traceability for the figure: owning docs,
Julia Core semantics references, physical/circuit model references,
implementation references, `core_export_fixture`, light/dark SVG output paths,
and review status. Register the manifest in
`docs/assets/circuit_draw/registry.yml`.
When SCQ_Design owns the reusable physics, include its canonical HTTPS `.qmd`
path in `canonical_physics_urls` and keep `physical_model_refs` as the
child-local routing adapter.

## Export-Backed Authoring

1. Build a reusable component in Julia Core, or build a complete research
   `CircuitPlan` in its owning project, and return an inspectable plan with
   `SchematicLayoutIntent`.
2. Add an explicit producer for `schematic_export.json`. Workbench-owned
   reusable components and Pluto examples register their builder and fixture
   path in `scripts/build/export_pluto_schematic_exports.jl`.
3. If `render_hints.schemdraw.component_type` is new, add one renderer-side
   visual component and one explicit dispatch case in
   `schemdraw_circuit_library.rendering.from_schematic_export`.
4. Add `draw.py`, `diagram.yml`, and the registry entry.
5. Export before rendering:

```bash
julia --project=core/julia/SuperconductingCircuitsCore \
  scripts/build/export_pluto_schematic_exports.jl
```

The exporter currently writes its complete supported fixture set; it has no
single-diagram selector.

A minimal export-backed `draw.py` is:

```python
from pathlib import Path

import schemdraw
from _lib.style import Theme, circuit_drawing
from schemdraw_circuit_library.rendering import (
    add_schematic_export_to_drawing,
    load_schematic_export,
)

SCHEMATIC_EXPORT_PATH = Path(__file__).with_name("schematic_export.json")


def build_drawing(theme: Theme = "light") -> schemdraw.Drawing:
    with circuit_drawing(theme=theme) as drawing:
        add_schematic_export_to_drawing(
            drawing,
            load_schematic_export(SCHEMATIC_EXPORT_PATH),
            theme=theme,
        )
    return drawing
```

Render and review one diagram first:

```bash
uv run python scripts/build/render_circuit_drawings.py \
  --diagram reusable.interdigitated_capacitor
uv run python scripts/build/render_circuit_drawings.py \
  --check --diagram reusable.interdigitated_capacitor
```

`--diagram` accepts a registry `diagram_id` and may be repeated. When the
targeted result is correct, validate export freshness and manifest ownership:

```bash
julia --project=core/julia/SuperconductingCircuitsCore \
  scripts/build/export_pluto_schematic_exports.jl --check
uv run python scripts/test/check_circuit_drawings.py
uv run python scripts/build/render_circuit_drawings.py --check
```

Finally, reference both SVG variants from each owning documentation page with
the shared `circuit-figure` wrapper. Do not hand-edit generated SVG files.

## Legacy Direct-Python Figures

Four earlier Pluto teaching figures still construct a visual component directly
inside `draw.py`:

- `pluto.transmission_line_circuit_model`
- `pluto.readout_line_purcell_filter`
- `pluto.readout_line_hanging_qwr_mtl`
- `pluto.readout_purcell_hanging_qwr_mtl`

They remain supported documentation assets, but they are not the template for
new reusable-component or Circuit Plan diagrams. Keep their existing
`build_drawing` contract and migrate them only when a Julia export contract
already exists; do not invent a parallel exporter merely to remove legacy code.

Direct sources must use `_lib.style.circuit_drawing(...)`, chained element
methods, anchors, and `drawing.hold()`. They must not import Backend modules,
Julia modules, archived runtimes, or legacy Python circuit visualizers.

## Failure Guide

| Failure | Meaning and response |
| --- | --- |
| `stale .../schematic_export.json` | Julia semantics or layout intent changed. Run the exporter, review the JSON diff, then render and review both SVG themes. |
| Missing `schematic_export.json` or `core_export_fixture does not exist` | Add the fixture path to the Julia exporter and run it before the renderer. |
| Missing `render_hints.schemdraw` | The Julia export does not request a Schemdraw projection. Add explicit layout/render intent; do not infer it from netlist rows. |
| Unsupported `component_type` | Add the matching visual component and explicit renderer dispatch. Do not add a permissive fallback. |
| `Rendered SVG differs` | The committed SVG is stale. Render the named diagram and review the generated light/dark diff. |
| Unknown diagram id | Use the exact `diagram_id` registered in `registry.yml`. |
| Ownership, link, or review-status failure | Fix `diagram.yml`, owning-doc links, or the draft/accepted state. Do not promote review status merely to satisfy the checker. |

## Review Status

Use `review.status: draft` for new or unreviewed diagrams.

Use `review.status: accepted` only when the diagram is accepted for use by the
owning documentation page in both light and dark themes. Stable documentation
pages must not reference draft diagrams.

The review status is a documentation asset gate. It does not make a figure a
machine-verification contract.

## Dependency Boundary

`core/python/circuit_libraries/` is the dedicated
`schemdraw-circuit-library` uv workspace package. The root `dev` dependency
group installs that workspace package, which owns the `schemdraw` dependency.
Run docs rendering through the root uv environment:

```bash
uv run python scripts/build/render_circuit_drawings.py
```

Do not add Schemdraw to Julia Core or application and production runtime
package dependencies for documentation drawing.
