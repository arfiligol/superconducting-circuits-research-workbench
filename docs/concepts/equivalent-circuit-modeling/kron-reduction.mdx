# Schur Complement and Kron Reduction

The reusable mathematical and network semantics are owned by the SCQ_Design
Knowledge Base:

- [Canonical knowledge: Schur Complement and Kron Reduction](https://github.com/arfiligol/SCQ_Design/blob/main/docs/knowledge/numerical-methods/schur-complement-kron-reduction.qmd)
- [Canonical knowledge: Admittance Coordinate Transforms](https://github.com/arfiligol/SCQ_Design/blob/main/docs/knowledge/network-modeling/admittance-coordinate-transforms.qmd)

This repository owns the executable entry points:

- `notebooks/pluto/includes/port_matrix_post_processing.jl` owns
  `apply_coordinate_transform` and `kron_reduce` for frequency-indexed
  `PortMatrixStack` admittance data.
- `notebooks/pluto/02_floating_lc_xy_line.jl` demonstrates one local
  port-compensation, real-coordinate-transform, and Kron-reduction workflow.
- [Floating Qubit Admittance Extraction](./floating-qubit-admittance-extraction/)
  records the unresolved solver-shunt, differential-normalization, and retained-
  load choices for that workflow.

The current implementation accepts an explicitly typed admittance stack and
uses a linear solve for the eliminated block. Exact-singular failure reports
the frequency and eliminated labels. It operates on the supplied port-space or
transformed-mode $Y$ matrix; it does not claim access to arbitrary internal
circuit nodes that are absent from that matrix.

Notebook 02 publishes the eliminated-block condition series and reconstruction
residuals. No implementation default decides which finite condition number is
acceptable: that threshold belongs to Human review for the intended downstream
decision.

Do not duplicate the derivation here. Update the canonical pages for reusable
semantics and keep Workbench-specific API, workflow, and artifact behavior in
this repository.
