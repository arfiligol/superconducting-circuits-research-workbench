## Current Executable Contract

`MTLCoupledRLGCSpec` currently stores:

| Field | Meaning |
| --- | --- |
| `start1_m`, `start2_m` | coupled-window start measured from each ladder head |
| `length_m` | exact physical coupling-window length |
| `section_length_m` | maximum/reference section length |
| `l_matrix_per_m_h` | symmetric positive-definite $2\times2$ terminal-domain $L'$ matrix in H/m |
| `c_matrix_per_m_f` | symmetric positive-definite $2\times2$ Maxwell $C'$ matrix in F/m, with $C'_{12}\le0$ |

Despite the type name, the coupled matrix path has no $R'$ or $G'$ matrix
fields. Its section overrides use zero series resistance and zero shunt
conductance, and the window rejects ladders with nonzero base or coupled-section
$R'/G'$. This is an **LC-only, lossless consumer capability**, not evidence
that an upstream extractor measured zero loss.

## Actual API

Construct the matrix model, use it for each line's coupled-section override,
then add the finite window:

```julia
model = MTLCoupledRLGCSpec(
  start1_m=2.25e-3,
  start2_m=0.0,
  length_m=1.5e-3,
  section_length_m=0.75e-3,
  l_matrix_per_m_h=[L11 L12; L12 L22],
  c_matrix_per_m_f=[C11 C12; C12 C22],
)

line1_override = coupled_line_section_override(model, 1)
line2_override = coupled_line_section_override(model, 2)

window = couple_transmission_window!(
  plan;
  id="readout_qwr_mtl_window",
  line1=line1,
  line2=line2,
  model=model,
  coupling_orientation=:same_direction,
)
```

There is no executable `add_coupled_line_section!` API. The supported path is
`MTLCoupledRLGCSpec` plus `coupled_line_section_override` and
`couple_transmission_window!`.

An even/odd constructor is also available. It accepts
`z_even_ohm`, `z_odd_ohm`, `phase_velocity_even_m_per_s`, and
`phase_velocity_odd_m_per_s`, then converts that symmetric lossless
specification into the same $L'/C'$ matrix representation.

## Maxwell Matrix Lowering

For one actual section length `dx`, Core reconstructs the physical circuit as:

| Element | Value |
| --- | --- |
| line-1 series self inductance | `L[1,1] * dx` |
| line-2 series self inductance | `L[2,2] * dx` |
| physical mutual inductance | `L[1,2] * dx`, with orientation sign applied while lowering |
| line-1 ground shunt | `(C[1,1] + C[1,2]) * dx` |
| line-2 ground shunt | `(C[2,2] + C[2,1]) * dx` |
| physical cross capacitance | `-C[1,2] * dx` |

Ground and cross capacitances are split in half across the two pi-section
boundaries. Using `C[1,1]` or `C[2,2]` directly as the ground shunt would
double-count the cross capacitor and fail to reconstruct the supplied Maxwell
matrix.

## Spatial Orientation

| Value | Boundary pairing | Mutual-inductance sign |
| --- | --- | --- |
| `:same_direction` | corresponding section and boundary order | positive input orientation |
| `:opposite_direction` | line 2 section and boundary order reversed | negated while lowering |

The input matrices do not change when a physical ladder is placed in the
opposite direction. The helper changes the spatial node pairing and the branch
current-reference sign.

Window boundaries must resolve exactly to generated section boundaries, and
paired sections must have the same physical length. Core does not silently
snap or interpolate the requested window.

## Not Yet Proven

- $R'/G'$ matrix ingestion and distributed loss lowering
- general $N$-conductor matrix support
- a project-wide signed/unsigned $L_{12}$ input convention
- analytic MTL response or section-refinement convergence
- a schema-validated Q2D envelope carrying terminal order, reference,
  extraction frequency, quantity availability, and solver provenance

Those limits are review gates, not notebook defaults.
